# 01 · GitHub 生态调研（行测/公考做题数据）

> 调研时间：2026-10-26　｜　数据来源：GitHub Search API（按 star 排序）+ 各仓库 README
> 目的：搞清楚「做题数据分析」这块已有的东西做到什么程度、哪些能复用、哪些是空白。

## 一、结论先行

1. **题库不缺**。`ERRRC/xingcezhenti`（1.8k star）已把 2016–2026 国考+省考行测真题做成结构化 Vault：515 套卷、58,890 题行、39,463 张图，图片全本地化。
2. **刷题器不缺**。至少 5 个可跑的完整应用（Web/Android/PWA），功能高度同构：模块树刷题 + 错题本 + 收藏 + 计时 + 模考 + 学习统计。
3. **数据分析全是「浅层统计」**。所有项目的"数据统计"都止步于：题量、正确率、连续打卡、日历热力图、模块进度条、薄弱考点排行。
4. **没有项目做「决策级分析」**：时间-正确率二维定位（性价比/放弃策略）、蒙对校正、题序疲劳衰减、错因归因与再犯率、目标分数反推模块得分组合、成绩波动置信区间。**这是空白位。**
5. **没人解决「数据从哪来」**。所有项目都是"自己刷题才有数据"，没有项目做「从粉笔等外部 App 导入做题记录」。`YSMull/fenbi-helper` 走的是逆向粉笔接口（2020 年，已停更），不可依赖。

## 四、可直接借用的设计资产

1. **知识树**：`kaogong-shuati` 的 `lib/fenbi-tree.mjs`（行测六大模块 + 申论五题型 + 综应题型树），与粉笔口径一致，直接对齐用户认知。
2. **题目元数据设计**：`地区 / 年份 / 试卷名 / 模块 / 大类 / 考点 / 题号`，`GongkaoNaoku` 已实践，支持任意组合筛选。
3. **去重方法论**：联考同题会以多省卷重复收录（平均 2.32 卷/题，最多 778 卷），必须按「题」去重而非按「卷×题」。
4. **错因卡结构**：`xingce-review-pro` 的「错因卡 + 弱点档案」分离，且写入有幂等与门禁，值得照抄这套状态机。
5. **库分离**：题库（只读）与用户学习库（可写）分库，备份只拷用户库。

## 五、合规与风险

- **题库版权**：`kaogong-shuati` 明确声明 `tiku.db` 版权归**粉笔**等来源方，仅授权个人学习、禁止商用与二次分发。基于这些题库做公开产品有风险。
- **逆向第三方 App**：`fenbi-helper` 路线涉及破解登录与接口逆向，法律与技术双重风险，不作为需求。
- **OCR 题面**：识图出错会污染分析结论，必须带置信度并在低置信时拒绝入库（`xingce-review-pro` 的做法）。
- **数据稀缺**：GitHub 上没有任何「公考做题数据」的公开数据集（都是题目，没有作答记录）。**所以作答数据只能自己产生或用户录入——这是本项目最大的约束。**
