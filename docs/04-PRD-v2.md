# 04 · PRD v2（最终版）：行测模考分析器

> 本文取代 [02-需求拆解.md](./02-需求拆解.md) 与 [03-MVP-模考波动分析.md](./03-MVP-模考波动分析.md) 的范围部分；
> 口径以本文第 3 节为准。数据事实来自 `docs/如风刷题.xlsx` 与两张「行测分数计算器」截图。

## 1. 一句话定义

**一个在自己电脑上双击就能用的行测模考记录与分析工具**：录入每次模考 12 个子题型的答对数与用时，自动算分，输出 6 个模块 × 4 条曲线，并判断"这次波动是不是真退步"。

## 2. 形态决策：为什么是电脑本地程序，不是手机小程序

| 形态 | 需要什么 | 结论 |
|---|---|---|
| 微信小程序 | AppID、ICP 备案、审核、后端（本地存储会被清缓存清掉） | ✗ 只自己用不值得 |
| Android / iOS App | 签名证书 / 开发者账号、打包、安装、迭代慢 | ✗ 成本高 |
| **电脑本地程序（选定）** | 双击启动，数据存本地文件，改完立即生效 | ✓ |

实现形态：**本地 Web 应用**（Node 本地服务 + 浏览器界面），双击 `启动.bat` 打开，观感与桌面 App 一致；数据存本地 SQLite 文件，可整文件备份。

发布形态：已用 **Node SEA** 打成单文件 `dist\行测模考分析器.exe`（约 90MB），PE 子系统设为 GUI，**不弹控制台窗口**；静态资源与 11 次历史数据全部内嵌，首次运行在 exe 同目录生成 `data\`。日志写入 `data\app.log`，退出走「设置 → 退出程序」。

## 5. 指标定义（全部可计算、口径固定）

| 指标 | 公式 | 说明 |
|---|---|---|
| 子题型正确率 | 答对 / 题量 | 百分比 |
| 子题型得分 | 答对 × 每题分值 | |
| 模块正确率 | Σ答对 / Σ题量 | |
| 模块得分 | Σ子题型得分 | |
| 总得分 | Σ模块得分 | 恒等于 100 − 失分 |
| 总用时 | Σ子题型用时 | |
| 平均每题用时 | 用时 × 60 / 题量 | 秒 |
| 得分波动 σ | 总体标准差 | 当前 5.5 |
| 期望分 E | Σ(题量 × 历史正确率 × 分值) | 历史正确率默认取最近 5 次 |
| 噪声 SE | √(Σ 分值² × 题量 × p × (1−p)) | 同一结构卷的随机波动 |
| 发挥偏差 δ | 实际得分 − E | \|δ\| ≤ SE 判「正常波动」 |

> 因为每次模考的题量/分值结构完全一致，**分数可直接横向比较**，不需要卷面难度校正——这是本工具比通用方案更简单也更准的地方。

## 6. 范围

### 做

1. 录入一次模考（12 行 × 答对数、用时）
2. 自动算分、正确率、模块汇总
3. 6 个模块 × 4 条曲线（正确率 / 得分 / 总用时 / 平均每题用时）
4. 记录列表：查看、编辑、删除
5. 单次诊断：这次波动是否超出噪声、分差落在哪个子题型
6. 导出：长图 PNG、CSV 备份
7. 一键导入历史 xlsx（完成首次迁移）

### 不做

- 不做题库、不做刷题、不做错题本（已有工具负责）
- 不做账号、云同步、多用户
- 不做手机小程序 / App 上架
- 不做 AI 讲题、申论

## 7. 功能需求

### FR-1 录入页（P0）

- 复刻「行测分数计算器」的分组结构：6 个模块分块，12 个子题型，每行显示「共 N 题，每题 X 分」
- 每行两个输入：**答对题数**（整数，0..题量）、**用时**（分钟，可小数）
- 实时显示：该行正确率、该行得分、模块小计、总分、总用时
- 输入校验：答对数 > 题量时标红并禁止保存；用时为空允许保存（曲线自动断点）
- 键盘流：`Tab` 依次跳转，`Enter` 跳到下一行答对数，录完一键保存
- 保存后停留当前页，可「再录下一次」或跳转曲线页
- 进度：录入草稿自动保存（关掉再开不丢）

**验收**：输入 24 个数字 ≤ 60 秒；总分与手算一致。

### FR-2 曲线页（P0）

- 顶部：总分走势（得分柱 + 总用时线，双轴）+ 5 个 KPI（最近得分、均值、σ、最高/最低、平均用时）
- 6 张模块卡，每卡 4 个面板：正确率(%) / 得分 / 总用时(min) / 平均每题用时(s)
- 子题型为不同颜色折线；单子题型模块自动隐藏图例
- 悬停显示该次全部子题型数值；末端标注最新值
- 数据点少于 2 个时显示「数据不足」占位
- 响应式：电脑 2 列，窗口变窄自动 1 列

**验收**：与 `docs/如风-题型曲线.html` 的图形与数值完全一致（该页即本需求的视觉基准）。

### FR-3 记录管理（P0）

- 列表：次数、总分、正确率、总用时、备注
- 操作：编辑（回到录入页）、删除（二次确认）、插入历史记录（自动重排次数）
- 空状态引导：导入历史数据 / 新建第一次

### FR-4 单次诊断（P1）

- 「第 N 次」详情页：
  - 结论一句话：`本次 28.9 分，比期望低 3.7 分，在正常波动范围内（SE=4.2）`
  - 分差瀑布：按模块/子题型拆解 `实际 − 期望`
  - 用时对比：哪些子题型超时
- 判定规则固定，不用 AI：
  - `|δ| ≤ SE` → 正常波动
  - `δ < −SE` → 归因到 δ 最负的子题型；若该题型同时超时 → 判「时间分配问题」，否则「知识点问题」
  - `δ > +SE` → 高于预期，提示确认是否题目偏简单

### FR-5 导出（P1）

- 曲线长图 PNG（整页截图式，适合发微信）
- 全量 CSV / JSON 备份与恢复

### FR-6 目标分（P2）

- 设定目标总分 → 输出各模块应达正确率与当前缺口，按「提分空间/每题分值」排序

## 9. 数据模型

```sql
subtype(id, module, name, qty, pts, sort)           -- 12 行，可编辑（应对不同卷型）
exam(id, seq, name, date, note, created_at)         -- 一次模考；name 为卷名（可空）
exam_item(exam_id, subtype_id, correct, minutes)    -- 每次 12 行
setting(key, value)                                 -- 目标分、历史正确率窗口等
```

- `seq` 唯一，表示第几次；`name` 是卷名（如「如风12」），列表与曲线上显示
- 调整顺序：把某次移动到第 N 位，其余记录按顺序重排（服务端事务内先整体偏移再写回，避开唯一约束）

- `seq` 唯一，插入历史时顺延
- 题量/分值改版时新建一套 `subtype` 版本，历史 `exam` 绑定版本，避免口径漂移
- 题库（结构）与作答数据分表，备份可只导 `exam/exam_item`

## 11. 技术方案

- **后端**：Node.js ≥ 22（内置 `node:sqlite`，零第三方依赖）+ 原生 `http` 模块
- **前端**：原生 HTML/CSS/JS，不引框架（页面只有 4 个，避免构建链）
- **图表**：ECharts 5 本地文件（已下载至 `docs/vendor/echarts.min.js`）
- **启动**：`启动.bat` → `node server.mjs` → 打开 `http://127.0.0.1:3210`
- **打包**：`npm run build:exe` → esbuild 打包 → `node --experimental-sea-config` → postject 注入 → 改 PE 子系统为 GUI
- **参考实现**：`ERRRC/kaogong-shuati` 的零依赖 Node + SQLite + 静态页结构可直接借鉴

## 13. 开放问题（不阻塞 M1，可边做边定）

1. **用时精度**：现在都是整分钟，是否需要秒？（影响输入控件与曲线精度）
2. **模考结构是否恒定**：11 次都是 135 题同一分布吗？如果以后做省考/机构卷（题量不同），需要"卷型"概念——当前按"结构一致"设计。
3. **目标分**：如果有明确目标分，FR-6 可以提前到 P1。
4. 是否需要**按天**记录（同一天两次模考）？当前只按次数排序。

## 14. 多端：PWA 与数据迁移（2026-10-26 增补）

### 14.1 一套代码，两种存储

- 共享核心移到 `app/public/shared/`：`domain.js`（题型结构）、`metrics.js`（得分/期望/SE）、`validate.js`、`errors.js`。服务端与浏览器**引用同一份**，避免口径漂移。
- `js/store.js` 启动时探测 `api/health`：
  - 可用 → `store-http.js`，走 `/api/*`（电脑版 / exe）
  - 不可用 → `store-local.js`，用 IndexedDB（手机 / 静态托管）
- 页面只依赖 store 的方法（meta / listExams / getExam / createExam / updateExam / deleteExam / stats / exportAll / importExams），不关心底层。

### 14.2 PWA

- `manifest.webmanifest` + `icons/icon-{192,512}.png`，可「添加到主屏幕」，独立窗口打开。
- `service-worker.js` 预缓存 24 个资源；导航请求网络优先、失败回退缓存，静态资源缓存优先。
- 只有本地模式才注册 SW；电脑版（http store）不注册，避免开发时缓存旧文件。
- 手机（≤900px）曲线页按需渲染：`IntersectionObserver` 滚到可见才初始化，首屏从 25 个图表降到 2 个。

### 14.3 发布到手机

最省事：把 `app/public/` 里的全部文件传到任意静态托管（GitHub Pages / Cloudflare Pages / 自己的服务器），HTTPS 打开即可安装；数据存在手机浏览器里，不上传。

本地预览：`npm run serve` → `http://127.0.0.1:8080`（无 API，自动走本地存储）。

### 14.4 数据迁移

电脑「设置 → 导出 JSON 备份」→ 手机「设置 → 导入 JSON 备份」。导入按次数去重，重复的跳过并提示。

### 14.5 原生 APK（Capacitor）

已生成安卓工程（本机无 JDK/Android SDK，未在本机构建）：

- `capacitor.config.json`：`appId=com.xingce.analyzer`、`webDir=www`、`androidScheme=https`
- `android/`：Capacitor 7 工程，`compileSdk 36`、`minSdk 24`
- 图标：`python tools/make_android_icons.py` 生成自适应前景 + 旧版图标；应用名「行测模考分析器」
- 同步：`npm run build:www` → `npx cap sync android`（把 `app/public` 复制进 APK 资源）

**出 APK 两种方式**

1. GitHub Actions（无需本机环境）：推送仓库后，在 Actions 手动运行 `android-apk`，产物 `app-debug.apk` 在 Artifacts 里下载。工作流见 `.github/workflows/android.yml`。
2. 本地：安装 Android Studio（内含 JDK/SDK），打开 `android/`，Build → Build APK(s)。

APK 内没有 Node 服务，数据全部在 WebView 的 IndexedDB，完全离线；导出备份时若无法触发下载，会退化为「复制到剪贴板」。
