# 03 · MVP 方案：模考分数波动分析

> ⚠️ 本文为过程稿，范围与口径已由 [04-PRD-v2.md](./04-PRD-v2.md) 取代。其中 E / SE / δ 算法已并入 PRD 第 5 节。

> 依据 [02-需求拆解.md](./02-需求拆解.md) 的决策记录收敛：
> 痛点＝**模考分数波动大**；数据＝**已有 Excel**；形态＝**本地网页，只自己用**；路线＝**纯分析层**。

## 一、先把问题定义清楚

"分数波动大"是感受，不是问题。一次模考比上次低 6 分，可能是下面 5 件事之一：

| 来源 | 是否可控 | 判断方法 |
|---|---|---|
| ① 随机误差（蒙对蒙错、状态抖动） | 不可控，只能估计 | 理论标准误 SE |
| ② 卷面难度差异 | 不可控 | 卷面期望分 E 与历史基准的差 |
| ③ 模块结构差异（这套卷资料分析多/数量难） | 不可控 | 分模块期望分 E_m |
| ④ 真实水平变化（复习有效/退步） | **可控** | 校正分趋势 + 置信区间 |
| ⑤ 时间分配与节奏 | **可控** | 模块用时 vs 预算 |

**产品要回答的唯一问题**：这次波动是①②③（不用管），还是④⑤（要调整）？

## 二、指标与算法（模块级即可，不必逐题）

记一次模考共 M 个模块，模块 m 有 n_m 题，历史正确率 p̄_m（来自该模块最近 K 次记录，默认 K=5，可调）。

**1. 卷面期望分**

```
E = Σ_m ( n_m × p̄_m ) × 每题分值
```

**2. 理论标准误（随机波动带）**

```
Var = Σ_m n_m × p̄_m × (1 − p̄_m)
SE  = √Var × 每题分值
```

含义：同一水平的人考同一套卷，分数天然会落在 `E ± SE` 内约 68% 的时间，`E ± 1.96SE` 内约 95%。
经验值：135 题、平均正确率 0.6、100 分制 → SE ≈ 4 分，95% 区间约 ±8 分。
**结论先行：单次 ±5 分以内的波动，大概率是噪声，不该据此改策略。**

**3. 发挥偏差**

```
δ = 实际得分 − E
```

**4. 难度校正分（横向可比）**

```
S_adj = 实际得分 + (基准期望 − E)     // 基准期望 = 历史平均 E
```
只有 `S_adj` 的时间序列才反映真实水平，原始分数序列会把"卷难"误判成"退步"。

**5. 模块归因（可加和）**

```
δ_m = 实际模块得分 − n_m × p̄_m × 每题分值
Σ_m δ_m = δ
```

**6. 波动性质检验**

```
s = 历史 S_adj 的实际标准差
R = s / 平均SE
```
- `R ≈ 1`：波动全部符合随机预期 → 真实水平稳定，别焦虑。
- `R > 1.3`：存在系统性因素 → 查换卷难度、复习中断、状态、时间分配。
- `R < 0.7`：波动异常小，可能是记录口径不一致或题目重复。

**7. 趋势**

对 `S_adj` 做加权最小二乘（越近权重越大），输出斜率 + 95% 置信区间。
斜率区间跨 0 → 判「平台期」，不要因为单次高分就加码。

**8. 时间盈亏**

```
时间盈亏_m = 实际用时_m − 预算用时_m
```
与 `δ_m` 联合判断：`δ_m < 0 且 时间盈亏 > 0` → 时间分配问题；`δ_m < 0 且 用时正常` → 知识点问题。

## 三、三个输出屏（每屏只给 1 个结论 + 1 个动作）

### 屏 1 · 这次算不算失常
- 折线：历史 `S_adj` + 本次点
- 阴影带：`E ± SE`
- 大字结论三选一：
  - `本次 −6 分，在正常波动范围内（SE=4.2）`
  - `本次 −11 分，超出随机范围，需归因`
  - `本次 +9 分，高于随机范围，注意是否卷偏简单`

### 屏 2 · 分数去哪了（瀑布图）
- 起点：上次 `S_adj` → 本次
- 分解条：难度差异 / 各模块 δ_m
- 高亮贡献最大的 1 个模块，附该模块错题考点 Top3

### 屏 3 · 我是真的在进步吗
- `R` 值与判定
- 各模块 σ 排行（谁最不稳定）
- 趋势线斜率 + 是否平台期
- 动作建议（规则生成，非 LLM）：
  - `资料分析：本次 −4 分且超时 6 分钟 → 下周做 3 次 25 分钟限时训练`
  - `判断推理：连续 3 次低于期望 → 回看该考点错题，而不是继续刷题`

## 四、输入：Excel 模板（三张表）

尽量贴合"已有表格"，字段少、可空。

**Sheet 1 `attempts`（一次模考一行）**

| 字段 | 必填 | 说明 |
|---|---|---|
| attempt_id | ✅ | 唯一，如 `2026-10-20-国考模考3` |
| date | ✅ | 2026-10-20 |
| paper_name | | 卷名，用于识别重复卷 |
| source | | 国考/省考/机构模考 |
| total_score | ✅ | 实际得分 |
| total_questions | ✅ | 总题量 |
| total_minutes | | 总用时 |
| rank_pct | | 排名百分位（有则更好） |
| note | | 状态备注（失眠/中断等） |

**Sheet 2 `modules`（一次模考 × 模块一行）**

| 字段 | 必填 | 说明 |
|---|---|---|
| attempt_id | ✅ | 外键 |
| module | ✅ | 政治理论/常识判断/言语理解/数量关系/判断推理/资料分析 |
| questions | ✅ | 本模块题量 |
| correct | ✅ | 正确数 |
| minutes | | 用时（有则能判时间分配） |
| target_minutes | | 目标用时，可全局配置 |

**Sheet 3（可选）`points`（考点级，用于定位）**
`attempt_id / module / point / questions / correct`

> 有 Sheet 2 就能跑通全部 P0 结论；Sheet 3 只是把"资料分析不行"细化为"增长量计算不行"。

## 五、功能清单（P0，共 6 条，不再扩张）

1. 导入 Excel/CSV：字段校验、错误行定位、重复 `attempt_id` 提示、可覆盖更新
2. 数据管理：模考列表、增删改、单条修正
3. 屏 1 分数带图
4. 屏 2 归因瀑布图
5. 屏 3 稳定性与趋势
6. 结论卡导出 PNG（发群里/存档）

**明确不做**：刷题、题库、错题本、账号、云同步、AI 讲题。

## 六、技术方案（本地、单机、零后端）

| 项 | 选择 | 理由 |
|---|---|---|
| 构建 | Vite + React + TypeScript | 迭代快，类型约束分析字段 |
| 图表 | ECharts | 瀑布图/置信带/中文标签开箱可用 |
| 解析 | SheetJS | 浏览器直接读 xlsx，无需上传 |
| 存储 | IndexedDB（Dexie） | 纯本地、离线、无需服务 |
| 样式 | Tailwind | 快 |
| 计算 | 纯 TS 模块 `lib/metrics.ts`，无副作用 | 可单测、可换界面 |

```
src/
├─ lib/
│  ├─ schema.ts      # 表结构与校验
│  ├─ import.ts      # Excel 解析 → 规范化
│  └─ metrics.ts     # E / SE / δ / R / 趋势（纯函数，带单测）
├─ pages/
│  ├─ Import.tsx
│  ├─ Overview.tsx   # 屏1
│  ├─ Attribution.tsx# 屏2
│  └─ Stability.tsx  # 屏3
└─ store/db.ts
```

若想更轻：一个 `index.html` + CDN 版 ECharts/SheetJS，但不利于后续接逐题数据，不推荐。

## 七、里程碑

| 阶段 | 内容 | 时长 | 验收 |
|---|---|---|---|
| **M0** | 不写 UI。用脚本读你现有 Excel，跑出 3 个结论并与手算对账 | 1 天 | 口径确认，确认结论"有用" |
| M1 | 导入 + 屏 1 | 2 天 | 能看历史波动是否正常 |
| M2 | 屏 2 + 屏 3 | 2 天 | 能回答"分数去哪了"与"是否在进步" |
| M3 | 导出 + 边界处理 | 1 天 | 10 次模考 3 秒内出结论 |

## 八、验收标准

1. 用真实历史数据回测：能正确识别至少 1 次"实际是卷难而非退步"的模考。
2. 导入 20 次模考（含缺失 `minutes`）不报错，缺失字段自动降级分析。
3. 结论与手算 `E / SE / δ` 误差为 0。
4. 每个结论必须同时给出"判定依据数值"，不接受无依据的判断。

## 九、需要你提供的东西（下一步）

1. 现有 Excel 的**前 5 行 + 列名**（脱敏即可），我按实际字段对齐，避免让你改表。
2. 历史模考大概有多少次、跨多长时间。
3. 是否有每次的**模块明细**（题量/正确数）；有没有记**用时**。
4. 用的卷子分值是否统一（如 100 分 / 135 题），不同来源是否混在一起。

拿到 1、3 就能直接进 M0 对账。
