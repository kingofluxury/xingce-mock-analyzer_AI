> ⚠️ 本文为过程稿，范围与口径已由 [04-PRD-v2.md](./04-PRD-v2.md) 取代；保留用于追溯推理过程。

## 一、定位判断

现有项目已经解决了「刷题」，但把「数据分析」做成了**结果播报**（正确率多少、错了多少、连续几天）。
真正的需求是**决策**：接下来一周该练什么、哪些题型该放弃、时间该怎么分配、离目标分还差多少。

因此本项目定位为：

> **做题记录 → 诊断 → 决策** 的分析层。
> 不追求做第 6 个刷题器；优先做「能接入外部做题数据、并给出可执行结论」的分析工具。

两种路线，先选一条：

| 路线 | 内容 | 优点 | 代价 |
|---|---|---|---|
| **A. 纯分析层**（推荐起步） | 只管录入/导入做题记录 + 分析报告，不做题库与刷题 | 合规风险低、2 周可出可用版本、不与粉笔正面竞争 | 需要用户自己录入 |
| B. 全栈 | 题库 + 刷题 + 分析 | 数据天然结构化，闭环体验好 | 题库版权、工作量 ×3、本质是重复造轮子 |

建议：**A 起步，B 作为后续增强**（用开源题库填"练习"能力，分析层架构不变）。

## 二、用户与场景

### 2.1 用户

| 角色 | 描述 | 优先级 |
|---|---|---|
| P1 自学备考者（主） | 已在用粉笔/华图刷题，有历史数据但拿不到结构化记录；需要"下一步练什么" | 主 |
| P2 二战/多战考生 | 有跨月跨年的成绩对比需求，关心"是否真的在进步" | 主 |
| P3 研友小团体 / 带班老师 | 需要横向对比、班级学情 | P2，暂不做 |

明确**不做**：面向机构的商业化 SaaS、题库售卖、代刷。

### 2.2 核心场景（按频率排序）

| # | 场景 | 触发 | 期望输出 | 频率 |
|---|---|---|---|---|
| S1 | **今日复盘** | 刷完 30–60 题 | 今天错的题集中在哪 2 个考点；哪些是超时导致；明天先练什么 | 每天 |
| S2 | **模块诊断** | 每周 | 六模块「正确率 × 平均用时」四象限；性价比排序；该补哪个题型 | 每周 |
| S3 | **模考归因** | 每次模考 | 分数拆解（模块得分贡献）、时间分配是否合理、与上次差在哪 | 每 1–2 周 |
| S4 | **考前取舍** | 考前 30 天 | 目标分反推：哪些题型必须拿满、哪些投入产出比低应战略放弃 | 1–2 次 |
| S5 | **长期趋势** | 每月 | 各模块正确率趋势与波动区间；是否进入平台期 | 每月 |

**关键判据**：如果 S1 只需 10 秒就能看完并知道"明天干什么"，产品成立；如果只是给一堆图表让人自己解读，就是失败。

## 三、输入与输出

### 3.1 输入（最大约束）

| 来源 | 可行性 | 成本 | 风险 | 结论 |
|---|---|---|---|---|
| 手动快速录入（做对/做错 + 用时 + 考点） | 高 | 每题 5–8 秒 | 用户坚持不下来 | **MVP 必做**，做到极致快 |
| Excel/CSV 批量导入（模板） | 高 | 低 | 需要用户整理 | **MVP 必做** |
| 自建题库刷题（数据天然结构化） | 高 | 中高 | 题库版权 | 二期 |
| 截图 OCR（粉笔报告页/练习记录页） | 中 | 高 | 识别率、字段对齐 | 二期，带置信度与人工确认 |
| 粉笔等 App 接口导出 | 低 | 极高 | 逆向、合规 | **不做** |
| 浏览器插件读取页面数据 | 中 | 中 | 随页面改版失效 | 备选 |

**必须落地的设计原则**：录入一条记录 ≤ 3 次点击；支持"连续录同一套卷"；支持撤销；离线可用。

### 3.2 输出

- 屏幕看板（手机可看）
- 可分享的报告（PNG / PDF），因为备考者习惯发群里打卡
- 结构化导出（CSV/JSON），避免数据锁死

## 四、指标体系（核心设计）

现有产品只做到 L1/L2，差异化在 L3/L4。

### L1 结果层
- 做题量、正确率、总用时、平均用时/题、估算得分

### L2 结构层（维度：模块 > 大类 > 考点；地区/年份/卷别；题型）
- 各维度题量、正确率、用时
- 得分贡献度 = 该模块得分 / 总得分

### L3 过程层（差异化起点）
| 指标 | 定义 | 用途 |
|---|---|---|
| 超时题占比 | 用时 > 该考点目标用时 × 1.5 的题占比 | 找出"会但慢"的题型 |
| 单题用时分布 | P50 / P90，长尾 | 判断是普遍慢还是个别卡顿 |
| 单位时间得分率 | 正确率 ÷ 平均用时（归一化） | **性价比排序**，决定练什么/放弃什么 |
| 题序疲劳衰减 | 后半段正确率 − 前半段正确率 | 体力/节奏问题 vs 知识问题 |
| 连错长度 | 最大连续错误数 | 心态崩盘检测 |
| 改答案收益 | 改对 − 改错 | 是否"想太多" |
| 蒙对率 | 标记"不确定但答对"的比例 | 校正真实水平 |

### L4 认知层（真正的护城河）
| 指标 | 定义 | 用途 |
|---|---|---|
| 真实正确率 | 答对中扣除蒙对（估计值） | 避免虚假进步 |
| 掌握度 | 贝叶斯估计（后期可用 IRT/ELO） | 比"刷过=会了"可靠 |
| 再犯率 | 同一考点错两次及以上的题占比 | 判断复盘是否有效 |
| 稳定度 | 近 N 次同考点正确率标准差 | 区分"会"和"碰巧对" |
| 提分空间 | (目标正确率 − 当前) × 题量 × 分值 | 优先级排序 |
| 时间盈亏 | 实际用时 − 目标用时 | 资料分析/数量的核心矛盾 |

### 需求溯源表（痛点 → 指标 → 功能）

| 用户原话 | 指标 | 功能 |
|---|---|---|
| "我刷了很多题但不涨分" | 真实正确率、再犯率 | 错因归因 + 复盘有效性报告 |
| "资料分析总是做不完" | 时间盈亏、超时题占比、P90 用时 | 限时训练 + 超时题清单 |
| "不知道先补哪块" | 单位时间得分率、提分空间 | 性价比四象限 + 优先级建议 |
| "模考分数忽高忽低" | 稳定度、置信区间 | 成绩波动分析 |
| "只剩 30 天，学不完了" | 各题型边际收益 | 目标分反推 + 放弃清单 |

## 五、功能树与优先级

### P0（MVP，2–3 周）
1. **快速录入器**：选考点（三级树）→ 对/错 → 用时（计时器或手填）→ 可选错因 → 下一条。键盘快捷键 + 手机大按钮。
2. **CSV/Excel 导入**：固定模板 + 字段校验 + 错误行回报。
3. **模块看板**：六模块题量、正确率、平均用时、得分贡献。
4. **错题本 + 错因标签**（6 类：知识盲区 / 审题失误 / 计算失误 / 方法不当 / 超时 / 蒙）
5. **单次报告**：今日复盘 + 一次模考归因。

### P1（差异化，3–4 周）
6. **正确率 × 用时四象限**（性价比矩阵）
7. **趋势与热力图**（周/月，按模块）
8. **薄弱考点排行**（按提分空间排序，不按错误数）
9. **目标分数反推**：输入目标分 → 输出各模块应达正确率与时间预算
10. **周报导出**（PNG/PDF）

### P2（增强，择机）
11. 间隔重复复习队列（SM-2）
12. AI 归因（错因自动判定、复盘建议、讲题）
13. 自建题库刷题（接开源题库）
14. 掌握度模型（ELO/IRT）
15. 多用户/班级对比
16. 职位表 + 进面分数线匹配（数据源另议）

## 六、数据模型草案

```
user(id, nickname, target_score, exam_date, created_at)

paper(id, source, region, year, name, module_set)          -- 一套卷
question(id, paper_id, module, category, kp_id, qtype,
         stem, options, answer, difficulty, image_refs)     -- 题（题库只读）

kp(id, parent_id, level, name, target_seconds, weight)      -- 考点树，含目标用时

attempt(id, user_id, type[drill|mock|review], paper_id,
        started_at, finished_at, total_score, source[manual|csv|app])

attempt_item(id, attempt_id, question_id, order_index,
             selected, is_correct, duration_ms,
             confidence[1..3], changed_answer, is_guessed, session_phase[前/中/后])

error_tag(id, name, parent_id)                              -- 错因分类
item_error_tag(attempt_item_id, error_tag_id, note)

review_event(id, attempt_item_id, reviewed_at, result)      -- 复盘后再测
```

设计要点：
- `attempt_item.duration_ms` 是分析的地基，**没有它就没有 L3**。
- `session_phase` 用于疲劳衰减，可由 `order_index` 推导，保留冗余便于查询。
- 题库与作答分库（参考 `GongkaoNaoku` 的 `kaogong.db` / `users.db`），备份只拷用户库。
- 所有写入带 `event_id` 幂等（参考 `xingce-review-pro`）。

## 七、非功能需求

| 项 | 要求 |
|---|---|
| 形态 | 本地优先 Web（手机浏览器可用），可选 PWA；不做原生 App |
| 离线 | 无网可录入与查看 |
| 性能 | 1 万条作答记录，看板首屏 < 1s |
| 隐私 | 数据默认只存本地；不上传、不埋点 |
| 导出 | CSV/JSON 全量导出；报告 PNG/PDF |
| 兼容 | 微信内置浏览器可打开（分享场景） |
| 可迁移 | 题库可替换，不绑定任何数据源 |

## 八、验收标准（可测）

1. 录入 50 条记录 ≤ 3 分钟（含计时）。
2. 从 CSV 导入 500 条，字段错误能定位到行号。
3. 同一批数据，模块正确率与粉笔报告差异 ≤ 1%。
4. 生成「今日复盘」结论 ≤ 10 秒可读完，且必须包含 1 条可执行动作。
5. 报告导出图片在微信中可正常显示。

## 九、里程碑

| 阶段 | 目标 | 产出 |
|---|---|---|
| M0（3 天） | 不写代码，先用 Excel/脚本把手上的真实做题数据跑通 5 个核心指标 | 指标口径确定，验证"结论是否有用" |
| M1（2 周） | 录入器 + CSV 导入 + 模块看板 + 错题本 | 自己每天能用 |
| M2（2 周） | 四象限 + 趋势 + 薄弱排行 + 周报导出 | 可给研友用 |
| M3 | 目标分反推 + 题库接入 + AI 归因 | 完整闭环 |

## 十、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **用户不愿录入**（最大风险） | 产品无数据 = 无价值 | M0 先自用验证；录入做到 3 次点击；提供 CSV 模板与 OCR 兜底 |
| 题库版权 | 无法公开分发 | 分析层与题库解耦；只自带"题号/考点"不复制题干；商用前替换数据源 |
| 指标口径与粉笔不一致 | 用户不信任 | 以粉笔报告为基准做对账测试 |
| OCR 错误污染数据 | 结论错误 | 低置信不入库、人工确认、可追溯 |
| 过度分析 | 用户看不懂 | 每屏最多 3 个结论 + 1 个动作；图表默认折叠 |

## 十一、待确认（影响范围的 5 个问题）

1. **给谁用**：只自己用，还是要给研友/一群人用？（决定要不要账号体系）
2. **数据从哪来**：你现在做题记录在哪？粉笔里、纸质卷、还是 Excel？（决定 P0 是录入器还是导入器）
3. **最痛的一件事**：是"不知道练什么"、"时间不够用"、还是"分数不涨"？（决定首个指标）
4. **形态偏好**：本地网页 / 手机 App / 微信小程序？
5. **节奏**：多久要能用起来？（决定 M1 砍到多小）

## 十二、决策记录（2026-10-26）

| 问题 | 结论 | 影响 |
|---|---|---|
| 核心痛点 | **模考分数波动大** | 首个指标改为「成绩波动归因」，而非泛化的模块诊断 |
| 数据现状 | 已有 Excel/表格 | P0 以**导入器**为主，录入器降级为补充 |
| 使用范围 | 只自己用，本地网页 | 不做账号体系、不做服务端、不做权限 |
| 起步路线 | A 纯分析层 | 不碰题库版权，只处理作答数据 |
